# 北京缴费规则独立核验（2026-10）

核验日期：2026-10-12。地区：北京市。仅研究普通企业在职职工、下述特定渠道参保的灵活就业个人。已读 `docs/DEVELOPMENT.md`；本任务只修改本文件。

## 可执行结论

- 2026-10 普通职工社保基数上下限已核实为 **7270—36348 元/月**，不是旧年度上下限。养老单位 16%、个人 8%；失业双方各 0.5%；当前公开医疗缴费说明为单位 9.8%、个人 2%＋3 元。后续独立审核发现旧规单位大额互助1%与当前9.8%说明的衔接尚未闭合：不得擅自叠加，也不得宣称已证实包含。自动情景只展示有公开依据的已核部分，并把单位医疗互助口径列为额外缺口，禁止输出完整单位成本；生育不重复加项。
- **社保“每险种、每方按分四舍五入”的地方依据尚未查到**。不得把通用金额格式化当政策，也不得把以下整额例子当舍入证明。因此本轮不足以启用“官方精确社保合计/五险一金合计”；可展示已核参数、单独计算无需舍入的受限项目，或接受实际账单金额用于其他计算。
- 普通企业住房公积金 2026-07-01 至 2027-06-30：基数 **2540—36348 元/月**，常规比例 **5%—12%**，每方分别乘基数后四舍五入到整元再相加；12% 的每方上限 4362 元，总额 8724 元。已核来源能支撑常规公积金独立计算，但应排除低薪减缴、生活费职工、降缓缴及特殊分中心规则。
- 工伤不能默认一个全市统一费率。官方图表列单位 0.2%—1.9%、个人不缴，但图表未交代实际浮动与减征。该区间不能直接成为实际费率硬校验上限；须输入单位实际核定费率并进一步核验适用规则，缺值禁算单位总额。

## 未完成核验与禁用清单

1. 北京社保精确至分的法定/经办舍入方式、逐人逐险逐方和汇总的先后顺序：本轮未找到官方明文。不能以“通常四舍五入”补齐。
2. 当年度申报工资的精度、先取整还是先限高保低：本轮只核定基数上下限；不把实发工资直接等同缴费基数。养老受限独立计算应要求已核定整数元基数。
3. 工伤实际费率、单位浮动、阶段性减征：禁止默认0.2%或用图表范围替代单位核定单。
4. 公积金低薪个人减缴、领取生活费、降缓缴、非企业以及中直/国管/铁路分中心：未形成完整包，不能并入普通企业计算。最低基数和最低个人缴存额不是同一概念。
5. 历史月份、未来月份、新入职不足全年、新调入及机关事业职业年金、城乡居民社保、非所述渠道灵活身份：本报告不足以提供完整规则。
6. 国务院令844号已补齐正式刊载全文，见下节；但新增灵活就业自愿缴存仍授权地方制定具体办法，**不能仅据全国条例推断北京灵活就业公积金费率/基数**。

## 全国实缴分摊的法律依据（追加核验）

核验日2026-10-12。以下支持“由用户填入已核定实缴额”的分项模型；不提供地方费率和舍入，因此不改变北京完整规则包禁用结论。

### 社会保险

已打开[《中华人民共和国社会保险法》（2018年修正）官方全文](https://wjw.hubei.gov.cn/bmdt/ztzl/hbzyjk/fgbz__/202207/t20220701_4200696.shtml)，湖北省卫健委2022-07-01刊载，来源国家卫生健康委员会，沿革注明2018-12-29修正。本轮未检出替代该缴费分摊结构的后续修法；仅用于以下条文，不把旧文中的退休年龄等其他条文当作当前完整待遇规则。

| 条文 | 支持的模型 |
| --- | --- |
| 第10、12条 | 职工养老存在单位和个人两项缴费，不能把单位部分从个人工资重复扣除 |
| 第23条 | 职工医保由单位和职工共同缴纳；灵活身份另有个人缴纳规则 |
| 第33—35条 | 工伤由单位缴费，职工不缴；费率由经办机构按具体单位情况核定 |
| 第44条 | 职工失业保险由单位和职工共同缴纳 |
| 第53条 | 生育保险由单位缴费，职工不缴；医保合并缴纳时不能重复计入 |
| 第60条 | 职工应缴社保由单位代扣代缴，并须按月告知明细；输入应来自工资单或经办缴费记录，个人额与单位额分开 |
| 第74条 | 经办机构分别记录个人缴费及单位为其缴费，双方有权查询核对 |

### 住房公积金（2026第三次修订）

已打开人民日报2026-08-19第10版正式刊载的[国务院令第844号修改决定全文](https://paper.people.com.cn/rmrb/pc/content/202608/19/content_30175819.html)，明确自**2026-09-20**施行；同版[重新公布的《住房公积金管理条例》全文](https://paper.people.com.cn/rmrb/pc/content/202608/19/content_30175820.html)注明2026-08-10第三次修订，文末为新华社北京8月18日电。因此2026-10引用应以该版本为准，而非仅用2019版。另有[司法部、住建部负责人答记者问（新华社刊载，来源司法部官网）](https://www.xinhuanet.com/politics/20260818/51938c448c55493cbbb274f8439fc724/c.html)交叉确认施行日期。

| 条文 | 支持的模型 |
| --- | --- |
| 第3条 | 职工个人缴存额和单位为职工缴存额均属职工个人所有；这是账户归属，不代表均从个人工资扣除 |
| 第16条 | 个人与单位月缴存额分别计算，可接收两项独立实缴输入 |
| 第19条 | 个人额由单位从工资中代扣；单位缴存额和代缴个人额一起汇缴。工资净额只扣个人部分 |
| 第23条（本次改写） | 单位为职工缴存的公积金按规定计入有关成本费用，国家机关事业单位在预算列支；单位成本模型应加单位额，不再额外加个人额 |
| 第37条（新条号） | 个人与单位可查询本人/本单位缴存情况并申请复核，可作为用户取得实缴输入的路径 |
| 第49条（新增） | 灵活人员可自愿缴存、具体办法由设区的市级以上政府制定；不足以产生北京自动费率规则 |

在不含其他扣款、补贴和雇佣成本的限定模型中，产品可用：个人现金净额=税前工资−个人实缴社保−个人实缴公积金−个税；工资及五险一金成本=税前工资＋单位实缴社保＋单位实缴公积金。此处是基于分担关系的算术模型，不是法律定义的全部“用工成本”。个税可税前扣除额须另外按税法范围核验，不能因输入了实缴额就保证全部可扣；税后反推还应明确实缴输入在反推期间固定，不随工资自动重算。

本轮形成的是参数证据与受限子项研究，不是“北京全部险种已审核通过”的完整包。验证仅涉及文档、官方原文与手算；没有改动实现或运行应用测试。
